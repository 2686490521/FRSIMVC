## 3. 缺失场景的具体约束

1. 对每个视图单独按 seed 生成随机缺失超像素，目标缺失率由 `MISSING_RATE`/`--missing-rate` 控制。
2. 若某个超像素在所有视图中同时缺失，随机恢复其中一个视图，保证 V5 的掩码共识分母不为 0。
3. 输入 GAE 的缺失行被置为全 0，同时保存未破坏的目标特征；重构损失只计算观测行。
4. 局部特征 KNN 图只由观测节点构造，缺失节点不会因 0 填充而产生虚假相似边。
5. 共享空间图不依赖模态特征，因此缺失节点仍能通过地理邻接关系传播信息。
6. K-means 原型仅用该视图的观测节点拟合，但可对所有节点输出软标签；签名、全局共识及一致性损失均显式使用观测掩码。

注意：掩码修复采用“安全交换”，在可行时同时维持每个视图的目标缺失数并消除全视图同时缺失。全场景两个视图本次实际缺失率均为 0.29987185；去除背景超像素后，有效训练节点上的比例会因抽样波动略有变化。程序会把每个视图的实际缺失率写入 `artifacts/missingness.json`。

## 9. 消融阶梯设计

把 V0–V5 拆成**四把独立开关**，逐级打开构成 A0–A4：

| 档位 | 含义 | `mask_aware` | `spatial_graph` | `csata_alignment` | `global_consensus` |
|---|---|:--:|:--:|:--:|:--:|
| **A0** | V0 + 30% 零填充（朴素，完全无掩码感知） | ✗ | ✗ | ✗ | ✗ |
| **A1** | A0 + 掩码感知重构 / 仅观测节点 KNN 图 | ✓ | ✗ | ✗ | ✗ |
| **A2** | A1 + 共识空间图融合（V2，权重 `graph_beta`） | ✓ | ✓ | ✗ | ✗ |
| **A3** | A2 + CSATA 空间签名 + Sinkhorn 对齐（V3+V4） | ✓ | ✓ | ✓ | ✗ |
| **A4** | A3 + 全局语义共识（V5 完整模型） | ✓ | ✓ | ✓ | ✓ |

不传 `--ablation-variant` 时读 config 的四个开关（默认全为 `true`，等价 A4，即原始完整 V5 行为不变）。

**A0 的“朴素”是彻底的**：除重构损失不再只看观测行外，KMeans 原型也在**全部节点**（含零填充行）上拟合。
为此引入第五个派生开关 `mask_aware_eval`（默认跟随 `mask_aware`），避免 A0 通过“只在观测节点上拟合原型”偷偷获得掩码信息。

对应实现（新增文件）：

## 10. graph_beta 扫描

`graph_beta` 控制融合图 `A^(v) = β·A_s + (1−β)·A_f^(v)`：

- `β=0` → 纯局部特征图；
- `β=1` → 纯共享空间图；
- 默认 `0.5`。

扫描集合建议 `β ∈ {0, 0.1, 0.25, 0.5, 0.75, 1.0}`，只在 A2/A3/A4 上展开（A0/A1 没有融合图）。
命令见 4.1 节的 `BETA_VALUES_STR`。聚合表会把 `beta` 单列输出，便于挑选最优点后再动自适应模块。

## 11. 诊断量落盘（对应大纲的诊断要求）

`artifacts/diagnostics.json` 字段：

| 字段 | 含义 |
|---|---|
| `transport_confidence_C_T_mean` | `C_T = (1/K)Σ_k max_j T_kj`，越高说明该视图的簇→全局锚点映射越确定 |
| `transport_entropy_H_T_mean` | `H_T = −(1/K)Σ_kj T_kj log(T_kj+ε)`，越低说明传输越锐利 |
| `signature_separation_D_inter` | 各视图签名 `q_i` 的平均两两 L2 距离，反映签名判别性 |
| `graph_diagnostics_D_G` | 直接内嵌 `graph_diagnostics.json`（连通分量、代数连通度、保边率） |
| `clustering.confusion_matrix` | `GT类 × 预测簇` 计数矩阵（用**原始 argmax 簇 id**，不做匈牙利映射） |
| `clustering.cluster_sizes` | 每个预测簇的样本数 |
| `clustering.per_gt_class` | 逐真实类的 support / 被某簇召回的比率 / 主导簇 |
| `clustering.per_cluster` | 逐簇的规模占比 / 纯度 / 主导真实类 |
| `clustering.num_gt_classes` vs `num_predicted_clusters` | 类别数是否对齐，可直接暴露“簇数≠类数”问题 |

关键点：混淆矩阵必须用**未做匈牙利映射**的原始簇 id，否则类别置换会被吸收掉，看不到真正的簇混叠/分裂。
`H_T`、`C_T`、`D_inter` 在 A0–A2（无 CSATA）下也会计算，只是传输退化为恒等矩阵（此时 `C_T=1.0`、`H_T=0.0`），
可作为“对齐模块到底带来什么变化”的对照。

# 第三部分：大纲v3 —— Mask-before-SLIC 协议（2026-09-17 深夜）

> 本部分推翻了第 1–14 节所描述的缺失注入顺序。第 1–14 节记录的是 **v2 协议**（先 SLIC 分割干净影像，再按超像素节点 id 注入缺失），
> 该协议存在一个**构造层面的循环依赖**：掩码按超像素节点 id 定义，而节点 id 来自 SLIC，所以掩码在逻辑上不可能早于分割。
> 结果是超像素划分、`y_full`、空间共识图、锚点中心在上游全部是干净的，缺失只作用于"节点特征置零"与"建图输入"两个末端环节。
>
> 第 15 节起改按《大纲v3》把掩码注入**前移到像素级、SLIC 之前**，并新增 `block` / `strip` 两种缺失协议。
> **两套协议的数字不得混用**：v2 的数字是"节点级缺失 + 干净结构先验"，v3 的数字才是"图像级缺失"。

## 15. 协议变更：掩码注入点前移

### 15.1 流水线对比

| | v2（第 1–14 节） | **v3（本部分）** |
|---|---|---|
| 掩码定义域 | 超像素节点 id | **像素平面 `(H, W)`** |
| 掩码注入时机 | SLIC **之后** | **SLIC 之前** |
| SLIC 输入 | 干净影像 | **受污染参考视图** |
| 超像素划分 | 与缺失无关（常量） | **随缺失变化** |
| 节点特征聚合 | 干净特征 → 置零 | 由污染像素聚合 |
| 建图输入 | 干净特征 / 零填充影像 | 由污染像素导出 |
| 预处理统计量 | 全图（含缺失像素） | **仅观测像素** |

新流水线：

```
Raw View ──▶ Mask(pixel) ──▶ Observed-only 预处理(PCA+minmax)
         ──▶ SLIC(受污染参考视图 v=0) ──▶ 特征聚合
         ──▶ 建图 ──▶ {A0 原版 FedRSMVC | A1..A3 FSRIMVC}
```

关键约束（大纲v3 §6）：SLIC **只跑一次**，在受污染的参考视图上，分割结果共享给所有客户端（`P_i^(1)=…=P_i^(V)`）。
落盘标记 `MASK_STAGE = 'pixel_level_before_slic'`，写入 `run_metadata.json` 与 `artifacts/missingness.json`。

### 15.2 循环依赖的消除

v2 里 `generate_random_view_masks(n_views, y_full.size, ...)` 的尺寸参数 `y_full.size` 来自 `sp_labels`，而 `sp_labels` 来自 SLIC，
因此"污染先于分割"在该定义下**不可能实现**。v3 把掩码改为像素级 `M^(v) ∈ {0,1}^{H×W}`，
先做 `X_corrupt = M ⊙ X`，再对 `X_corrupt` 求分割，依赖方向才理顺。

### 15.3 无泄漏预处理

`observed_only_minmax`：PCA 与 min-max 归一化的统计量只由**观测像素**估计，缺失像素不参与，因此不会把真值信息漏进归一化尺度。
在 `rho = 0` 时它与原 `minmax_scale` **逐位相同**，所以完整数据臂与 v2 的历史完整数据结果可比。

## 16. 三种缺失协议（一个实现，像素率精确）

新增 `utils/missing_simulator.py`（纯 numpy 零依赖，两个仓库各一份、**字节相同**），
`generate_pixel_masks(n_views, H, W, missing_rate, seed, mode, params) -> (V, H, W) bool`（`True` = 观测）。

| mode | 几何形态 | 默认参数 | 模拟的故障 |
|---|---|---|---|
| `random` | 散点小补丁（边长 3%–7% 的矩形，随机散布） | `patch_scale=[0.03,0.07]` | 随机像元丢失 / 噪声 |
| `block` | 大块矩形或不规则区域 | `block_scale_h=[0.1,0.3]`, `block_scale_w=[0.1,0.3]`, `irregularity=0.25` | 连续遮挡（云、建筑、传感器坏区） |
| `strip` | 整跨度条带（可竖向/横向） | `strip_width_scale=[0.03,0.09]`, `strip_orientation=auto`, `strip_layout=periodic` | 条带故障 / coverage gap |

三种协议共用一个"矩形填充画布"内核：

1. 所有模式都退化为"往画布上放矩形"，只是矩形尺寸分布与放置策略不同；
2. 最后一个矩形用**保形收缩** `_shrink_to` 裁剪，使掩码恰好含 `round(rho · H · W)` 个缺失像素；
3. `block` 的锯齿边通过"每行同宽、整行平移"实现，**面积守恒**；
4. `strip` 的周期布局用自适应间距 `_periodic_state` 计算；当游标饱和或连续 40 次无进展时回退到随机放置，避免死循环。

**像素率精度实测**（第一轮全部 140 个 run）：请求 `rho=0.3` → 实测 `pixel_missing_rate = 0.3000 / 0.3000`（两个视图），
与 `round(rho·H·W)` 的偏差 ≤ 5e-6。

## 17. 节点可用性判定与修复

缺失在像素级定义后，需要在超像素级重新定义"这个节点在这个视图里算不算可见"：

- 观测比 `r_i^(v) = |P_i ∩ observed| / |P_i|`（`node_observed_ratios`）
- 可用掩码 `m_i^(v) = 1[ r_i^(v) ≥ τ ]`（`derive_node_masks`），阈值 `superpixel_observed_threshold`，默认 `τ = 0.5`
- 全视图同时缺失的节点由 `repair_all_missing_nodes` 在**观测比最高的视图**里复活（`ensure_node_coverage`，默认 `True`）

实测（第一轮，`rho=0.3`，random，10 seeds）：

| 数据集 | 超像素节点（rho=0 → rho=0.3） | 有效节点 | 节点级缺失率（view0 / view1） | 强制修复节点数 | 全视图缺失 |
|---|---|---|---|---|---|
| Trento | 2341 → 2725–2809 | 1042 → 1146–1197 | 0.2649–0.2770 / 0.2087–0.2275 | 223–255 | **0** |
| MUUFL | 1789 → 1798–1856 | 1789 → 1798–1856 | 0.2536–0.2737 / 0.2180–0.2415 | 149–196 | **0** |

三点判读：

1. **节点级缺失率 < 像素级缺失率**（0.26 vs 0.30）。这是 `τ=0.5` 语义的必然结果：一个超像素有半数以上像素可见就算可见，因此部分遮挡不产生节点级缺失。这是本协议的设计选择，需要写进论文。
2. `all_views_missing = 0` 全部成立，说明覆盖修复生效。
3. **修复量不可忽略**（Trento 约 223–255 / 2770 ≈ 8–9%）。这是 `ensure_node_coverage=True` 的直接后果，属于协议层面的决定。

### 21.9 稳定性复核：基线的 Trento 优势只存在于"最高点"这一个统计量上（2026-09-18 补）

**动机。** 我们报告的 ACC 是 300 轮里**最好一轮**的值（`metrics.json` 取 `history.csv` 的 `max`），不是最后一轮。
这是一个**极值统计量**：它的期望值随轨迹的抖动幅度单调上升，因此会**系统性偏袒抖动更大的一方**，
而不只是反映"哪一边聚类得更好"。§21.3 里"Trento 五项全输"这个结论就建立在这一个统计量上，需要单独复核。

**方法。** 对全部 **140 个 run** 逐轮读取 `history.csv`（300 轮 × 10 seed），为每个 run 计算 7 个统计量：

| 统计量 | 含义 | 性质 |
|---|---|---|
| `best` | 300 轮最大值 | **= 当前报告值**，极值 |
| `p25` / `median` | 逐轮 ACC 的 25 分位 / 中位数 | 典型表现 / 下限 |
| `mean` | 300 轮均值 | 典型表现 |
| `tail_mean` | 末 50 轮均值 | 训练末段的稳定水平 |
| `final` | 第 300 轮 | 收尾状态 |
| `p10` | 10 分位 | 最差区间的水平 |

再做**逐 seed 配对**比较（`delta = A3 − baseline`，n=10，paired t，df=9）。
脚本：`_audit/analyse_stability.py`、`_audit/analyse_stability_stats.py`；日志 `analysis/stability.log`、`analysis/stability_stats.log`。

**逐条读数：**

1. **抖动大 2 倍。** 基线 Trento 的逐轮 ACC 标准差是 **0.0746**，A3 是 **0.0365** —— 基线是 A3 的 **2.04 倍**。
   seed 之间的终值离散度同样如此：基线 `final` = 0.4482±**0.0988**，A3 = 0.5576±**0.0445**，基线是 **2.2 倍**。
2. **趋势是平的、甚至是负的。** 基线 Trento 前半程 0.4753 → 后半程 0.4714（**−0.0039**），拟合斜率 **−0.025×10⁻³/轮**：
   整条轨迹既没有收敛、也没有退化的稳定方向，就是**一条在 0.47 上下抖动的水平线**。
   A3 Trento 则是前半 0.5032 → 后半 **0.5520**（**+0.0488**），斜率 **+0.315×10⁻³/轮** —— 真正在爬升并停在一个高台上。

4. **A3 的最高点和自己的典型轮次差得很少。** 基线 Trento 的 `best − median` = **0.1538**，
   A3 只有 **0.0414** —— 即 A3 报告出来的那个"最高点"，几乎就是它的常态水平；基线的则是常态之上 0.15 的一次尖峰。

#### 21.9.3 峰值虚高的量化，以及一个必须说清的限定

用 `best − median` 除以"逐轮标准差"得到一个无量纲的**峰值虚高倍数**：

| 数据集 | 档位 | `best − median` | 逐轮 std | **比值** | `best_round` 中位数 |
|---|---|---|---|---|---|
| Trento | complete | 0.1600 | 0.1164 | 1.37 | 46.5 |
| Trento | **baseline** | 0.1538 | 0.0746 | **2.06** | 102.0 |
| Trento | A0 | 0.1015 | 0.0417 | 2.44 | 7.0 |
| Trento | A1 | 0.1096 | 0.0436 | 2.51 | 133.5 |
| Trento | A2 | 0.1269 | 0.0507 | 2.50 | 167.5 |
| Trento | **A3** | 0.0414 | 0.0365 | **1.13** | 158.0 |
| MUUFL | baseline | 0.0942 | 0.0281 | 3.35 | 105.5 |
| MUUFL | **A3** | 0.0566 | 0.0273 | **2.07** | 158.0 |

基线 Trento 的比值 **2.06** 意味着：它报告的最高点，位于自身逐轮中位数之上 **2 个标准差**；
A3 Trento 的比值 **1.13**，即最高点只在中位数之上 **1.1 个标准差**，属于正常平台噪声。

> ⚠️ **诚实限定（很重要）**：`complete`（全数据）臂的比值是 **1.37**，`A0` 是 **2.44**、`A1` 是 **2.51**、`A2` 是 **2.50**。
> 也就是说"峰值虚高"**并不是基线独有的毛病**，而是这套训练目标 + 极值统计量的**普遍现象**（连抖动最大的 `complete` 也有 0.16 的 `best−median`）。
> 因此本节的主张**不是**"基线作弊"，而是：
> **用极值统计量做跨方法比较，本身噪声极大、且偏袒高方差的一方；必须补一个非极值的口径。**

#### 21.9.6 口径建议（写论文/汇报时怎么用这一条）

1. **主表不要只报 `best`。** 至少并列 `median`（或末 30 轮均值）；否则结论对统计量高度敏感 ——
   本例中换一个统计量方向就反转，而且**两侧都显著**，属于典型的"口径决定结论"。
2. **报 `best` 时必须一并报逐轮 std 或 `best − median`**，让读者看到这个最高点有多"尖"。
3. 更稳的做法：报 **`p25` – `median` – `best`** 三档（或箱线图），把"下限 / 典型 / 上限"一起给出。
4. 对 Trento 这个具体对比，**诚实的说法是**：
   > 在 Trento 上，基线的**最高点**高于 FRSIMVC（0.6321 vs 0.5855，paired p = 0.008）；
   > 但在**典型轮次**上 FRSIMVC 反而更高（`median` 0.5441 vs 0.4783，Δ = +0.0658，p = 0.004），
   > 且逐轮方差只有基线的一半（0.0365 vs 0.0746）。基线在 Trento 上的优势**只存在于 300 轮里的一两次越界尖峰**。
5. **不要把这条当成"赢了基线"的证据。** §21.9.3 已说明极值虚高是这套训练目标的通病；
   本节的正确作用是**否证"基线在 Trento 上稳定更好"**，而**不是证明"A3 在 Trento 上更好"**。
   要证明后者，需要在**固定评估节点集**（见 §21.5 的警告）+ **统一统计口径**下重跑再比。
6. 顺带一个副发现（尚不能归因）：**`complete`（全数据）臂在 Trento 上也是负趋势**（前半 0.6528 → 后半 0.6067，斜率 −0.279×10⁻³/轮），
   说明**原版 FedRSMVC 的训练目标本身在后半程会退化**；而 A3 的趋势是 **+0.315×10⁻³/轮**。
   即我们加入的模块除了抗缺失，似乎还顺带修掉了原目标的一个训练稳定性缺陷 —— 这条值得在轮 2 里单独验证。

日志 `/tmp/stability.log`、`/tmp/stability_stats.log`（本地副本 `analysis/stability.log`、`analysis/stability_stats.log`）；聚合结果 `/tmp/stability.json`。

### 22.3 代码定位

`utils/superpixel_utils.py` 的 `create_spixel_graph` 在两个仓库不是同一个函数（md5 `f9ec4e99…` vs `ccd2116b…`），三处差异：

| 步骤 | 原版（基线仓库） | FRSIMVC 仓库 |
|---|---|---|
| kNN 的输入特征 | `minmax_scale(concat(超像素均值, 质心(x,y)))` —— **含 2 维空间质心** | `minmax_scale(超像素均值)` —— **不含质心** |
| 对称化 | 无（有向 kNN） | `maximum(A, Aᵀ)`（对称化，边数变多） |
| 输出前的归一化 | 无（原始 `exp(-d²γ)` 权重） | `_fuse_graph` → `normalize_sparse_adjacency(·, add_self_loops=True)`，即 `D^{-1/2} A D^{-1/2}` **且加自环** |

而 `models.py` 里 `adj` 是**直接**送进 `torch.mm(adj, support)` 的（无内部归一化），
所以"归一化 / 未归一化"不是无关紧要的尺度差异：原版每行权重和约 32，FRSIMVC 每行约 1。

这解释了 v2 记录里 P0-1（"A0 ≠ 独立基线"）的**全部机制**。需要强调的是：这三处差异**不是本次 v3 改写的产物**
（`superpixel_utils.py` 的 mtime 是 2026-09-16 20:57，早于 v3 改写），而是 FRSIMVC 代码库自带的。

### 22.6 影响与建议

1. **跨仓库的绝对数不可直接比较**。`baseline` 与 `A3` 之间既有"方法差异"又有"代码库差异"（建图器 + 训练流程），两仓库的 `complete` 臂也不可比。
2. **受控结论仍然成立**：§21.1 的受控性验证表明同一 grid 内的掩码逐位相同、跨仓库也相同，因此
   - 仓库内纵向比较（`complete` vs `A0..A3`，即 §21.4 消融阶梯）**有效**；
   - §21.3 的 `A3 vs baseline` 是"两个真实系统"的对比，有效但混淆来源不止一个；
   - §21.5 的"相对保持率"里 `rho=0` 基线受节点集变化影响，只能作指示。
3. **A0 不是原版 FedRSMVC 的忠实复现**。若论文要把 A0 当基线，需先对齐建图器 + 训练流程，否则 A0 会被自身代码库压低约 0.03–0.06 ACC。
4. **建议的下一步（待决策，未执行）**：
   - 短期：承认基线是独立实现，数字全部取自基线仓库（现状即可用）；
   - 彻底：把 A0 的建图器切到 `original` 语义，并逐项 diff 训练/评估代码，直到 `rho=0` 两仓库对齐，再作为"真·原版基线"。

## 28. V5 总体框架说明

### 28.1 一句话

**在"影像级（像素级）缺失"的多视图遥感数据上做联邦图聚类**：缺失注入发生在 SLIC 之前（Mask-before-SLIC），
节点级可用性由观测像素比例判定，客户端只上传 `K×3` 的簇级统计量，服务端用**平衡的空间-语义锚点传输**
把各客户端簇排到统一编号，再在观测节点上做全局语义共识。

### 28.2 数据流（协议 + 三个模块）

```
原始多视图影像 (H×W×B_v)
   │ ① Mask-before-SLIC          MASK_STAGE = pixel_level_before_slic
   ▼   每视图独立像素掩码；缺失像素数精确 = round(ρ·H·W)；
       随机 random / 块状 block / 条带 strip
观测像素-only PCA + 归一化（无泄漏：缺失像素不参与统计）
   │ ② 在受污染影像上重跑 SLIC → 共享分割
   ▼   ⚠ 代价：节点集随缺失种子变化（Trento 1042→1146–1197）
3D patch 特征聚合 → 节点特征 X^(v)；缺失节点置 0，同时另存 target
   │ ③ 节点可用性
   ▼   m_i^(v) = 1[ r_i^(v) ≥ τ ]，r_i = 超像素内观测像素比例，τ = 0.5
建图  ── 模块一雏形（当前为固定 0.5 融合，大纲v5 之后才上自适应 β_ij）
   ▼   A^(v) = 0.5·A_s + 0.5·A_f^(v)
       A_s   共享空间图（不依赖模态，缺失节点仍连通）
       A_f   仅由观测节点构造的特征 kNN 图（避免 0 填充造成虚假边）
联邦 GAE 逐轮训练（每客户端本地 1 epoch 重构 + 1 epoch 共识）
   ▼   embedding → 仅用观测节点拟合 KMeans → 原型 μ_k^(v) → 软标签 S^(v)
── 模块二 BSSAT（服务端；只看得到 K×3 聚合量，看不到任何私有特征）──
   ▼   q_spatial_k = D_K⁻¹ Sᵀ R U^c          （簇在共享空间基上的投影）
       q_semantic_k = [质量, 指派熵, 紧致度]   （客户端本地算，隐私成立）
       z_k = [q_spatial_k ‖ q_semantic_k]      （双签名）
       C_kj = λ_s·d_spatial + λ_c·d_semantic
       T^(v) = argmin <T,C> + ε·H(T)  s.t.  T1 = a^(v),  Tᵀ1 = b'
       b' = (1-α)·b + α/K                     （大纲v5 新增，§30）
       条件矩阵 = T / a  → 行随机，下游零改动
── 模块三（尚未实现）：跨客户端语义-空间补全 ──
   ▼
全局语义共识：按观测掩码对已对齐软标签加权平均
   ▼
一致性损失回传客户端 → FedAvg 聚合 → 下一轮
   ▼
评估：best-round 口径 → ACC/Kappa/NMI/ARI/PURITY
      + 集中度诊断（cluster_max_ratio / cluster_entropy / …）
      + MUUFL 前景指标（ACC_fg / NMI_fg / ARI_fg，y_i ≠ -1）
```

### 28.3 损失与目标

单客户端单轮（`client/FedAvg_client.py`）：

```
L = λ_rec · MSE( x̂[观测行], target[观测行] )
  + λ_cons · Σ_d KL( aligned_obs ‖ consensus_obs )      # 仅观测节点
```

默认 `λ_rec = λ_cons = 1.0`，`local_epochs = 1`，`n_epoches = 300`，Adam `lr = 1e-4`，`weight_decay = 1e-5`。
服务端每轮只改两件事：**全局锚点重心更新** 与 **全局簇质量 `b`（本轮为 `b'`）的动量累积**（默认 momentum = 0，即直接取本轮均值）。

## 29. 模块二 BSSAT（大纲v4 第一轮）：实现与结果

### 29.1 与 v3 CSATA 的真实增量

大纲v4 的模块二名义上有两处升级（双签名、平衡传输）。逐行核对代码后，**真实的算法增量只有一条**：

> v3 的 `sinkhorn_transport` **本来就在跑双边际 Sinkhorn**，只是两端的列目标都取**均匀分布 1/K**，
> 最后靠行归一化恢复行边际。BSSAT 的真实增量是：
> **把列边际从"均匀 1/K"换成"由各客户端簇质量聚合而来的真实全局簇质量 b（非均匀）"，并且不再被行归一化破坏。**

双签名（`q_semantic = [质量, 指派熵, 紧致度]`）确实是新增项，但它只是把 `C_kj` 从纯几何匹配
变成空间-语义匹配，属于**代价矩阵层面**的改动，不改变传输结构。

### 29.2 实验矩阵与批次

| 项 | 值 |
|---|---|
| 批次 | `results/bssat/_launches/20260918_145319` |
| 规模 | 180 job = **360 run**，全部 `completed` |
| 臂 | `A3`（v3 CSATA：空间单签名 + 行随机 Sinkhorn） vs `BSSAT`（双签名 + 平衡传输） |
| 扫描 | `β ∈ {0.3, 0.5, 0.7}` × `ε ∈ {0.02, 0.05, 0.1}` |
| 其它 | `ρ = 0.3`，`random`，`seed = 0…9`，`epochs = 300`，`τ = 0.5`，`λ_s = λ_c = 1.0`，`momentum = 0` |
| 口径 | **best-round ACC**（300 轮中最优轮写入 `metrics.json`） |

### 29.3 主结果：18/18 个单元全部正向

| 数据集 | 口径 | A3 | BSSAT | Δ | 逐 seed |
|---|---|---|---|---|---|
| Trento | pooled（n=90） | 0.5840 | **0.6008** | **+0.0168\*\*\*** | 75/90 胜 |
| MUUFL | pooled（n=90） | 0.3518 | **0.3932** | **+0.0415\*\*\*** | 89/90 胜 |
| Trento | 最优单元 β=0.5/ε=0.1 | 0.6081 | **0.6289** | +0.0208 | — |
| MUUFL | 最优单元 β=0.5/ε=0.1 | 0.3754 | **0.4069** | +0.0315 | — |
| MUUFL | 最大单格增益 β=0.7/ε=0.02 | — | — | **+0.0570** | — |

* **18/18 个 (数据集 × β × ε) 单元全部正向**，无反向格。
* **`ε` 是主导因子**：ACC 随 `ε` 单调上升（0.02 → 0.05 → 0.1）。
* 两个数据集的**最优单元都是 β=0.5 / ε=0.1**，与大纲v5 固定该组默认参数一致。

### 29.4 三个前提被实验推翻（重要）

大纲v4 的验收 KPI 中有一条"把折叠压到 ~0"。结果**不仅没压下去，而且方向相反**，
连带推翻了对 C_T/H_T 的解读：

| 被推翻的前提 | 实际结果 |
|---|---|
| ① "折叠（cluster concentration）是病征，应压到 ~0" | `r(折叠, best ACC) = +0.54 (Trento) / +0.45 (MUUFL)`，**折叠组 ACC 恒高于非折叠组**；折叠率 Trento 28.9%→50.0%、MUUFL 41.1%→98.9%。**KPI 不成立**。Trento 的增益 58% 来自"位移到折叠档位"，仅 42% 来自同档内改善。 |
| ② "`C_T` 越高 / `H_T` 越低 = 对齐越好" | 符号反转：`r(C_T, ACC) = −0.44 ~ −0.55`，`r(H_T, ACC) = +0.41 ~ +0.53`。**越"自信"的传输反而对应越低 ACC**，只能当描述量。 |
| ③ "ACC 涨 = 全面变好" | MUUFL ACC `+0.0415`，但 **NMI 0.2030→0.1751、PURITY 0.4533→0.4326**；Trento NMI 0.4010→0.3813。簇形态变成"一头极重 + 长尾极细"（MUUFL 最大簇 436.9→633.9，最小簇 49.2→1.0，最大簇纯度 0.6161→0.5744）——**与"避免多簇压向同一锚点"的设计初衷相反**。 |

### 29.5 口径决定结论：paired 六统计量的分歧

对 10 个 seed 逐轮配对，比较六个统计量（`best` / `median` / `tail_mean` / `p25` / `mean` / `final`）：

| 数据集 | `best` | 其余统计量 |
|---|---|---|
| MUUFL | `final` +0.0044 (ns) | median / tail / p25 / mean **全显著为正** |
| **Trento** | **+0.0168\*\*\*** | median / tail / final / p25 / mean **全部显著为负**（−0.015 ~ −0.025） |

Trento 上 BSSAT 的最优轮中位数从 150 移到 202，逐轮 std 从 0.0348 升到 0.0407。
⇒ **"BSSAT 更好"这个结论只在 best-round 口径下成立**，这与 §21.9 对基线稳定性的结论是同一条经验：
**主表不能只报 best，至少要并列 median / 末 30 轮均值。**

## 30. 大纲v5 本轮改动：BSSAT-v2 Tempered Global Anchor Mass

### 30.1 动机

平衡传输的列边际 `b` 来自各客户端自己的簇质量，这形成一个**正反馈环**：

```
大簇 → b_k ↑ → 该锚点拿到更多传输质量 → 对齐后簇更大 → 下一轮 b_k 更大
```

MUUFL 上表现为最大簇从 437 涨到 634、最小簇塌到 1。大纲v5 的对策**不动 Sinkhorn 求解器**，
只把传输的**目标分布**做一次凸插值。

### 30.2 公式与参数

$$\tilde b = (1-\alpha)\,b + \alpha\,u,\qquad u_k = \frac{1}{K}$$

* `α = 0` → 精确复现 BSSAT-r1（本轮作为**同批次对照**保留，不与旧批次比较）
* `α > 0` → 温和抑制主导锚点，但**不强制**各类完全均衡
* 扫描范围：`α ∈ {0, 0.05, 0.10, 0.20, 0.30}`；本轮**只扫这一个变量**

固定：`β = 0.5`、`ε = 0.1`、`ρ = 0.3`、`mode = random`、`arm = A3 + dual + balanced`、`seed = 0…9`、
数据集 `Trento + MUUFL` ⇒ `5 × 2 × 10 = 100 runs`（50 job × 2 数据集）。

> 本轮**不改** β、**不改** ε、**不做**模块一、**不做**模块三、**不恢复** A4。

### 30.4 指标口径变更（重要）

1. **best-round 口径不变**，仍以 `Best ACC` 为第一优先；
2. **新增 4 个 concentration diagnostic**（基于 best round 的簇占比 `p_k = n_k / N`）：
   `cluster_max_ratio`、`cluster_min_ratio`、`cluster_entropy`、`effective_num_clusters`；
   `effective_num_clusters` 比"预测簇数 < K"更有信息量；
3. **"collapse" 统一改名为 "cluster concentration"**，且**不再当健康指标**（它与 ACC 正相关）；
4. **MUUFL 固定输出前景指标** `ACC_foreground` / `NMI_foreground` / `ARI_foreground`（`y_i ≠ -1`）。
   论文正文口径**仍是 raw ACC**，前景指标只为防止"总 ACC 涨了但只是背景识别更好"；
5. **`C_T` / `H_T` 继续落盘，但只作 descriptive diagnostic**，不再写 `C_T↑ ⇒ alignment better`。

### 30.7 事后决策规则（大纲v5 §6）

跑完 100 runs 后按三种情况决策，**不要机械地选最高 ACC**：

| 情况 | 判据 | 决策 |
|---|---|---|
| **A** 真正双赢 | `ACC_Trento ≥ 0.629` **且** `ACC_MUUFL ≥ 0.407`，同时 `NMI/PURITY ↑`、`p_max ↓`、`H_clu ↑` | 确定采用 **BSSAT-v2**，模块一/三都建立在它之上 |
| **B** ACC 几乎不变但结构明显改善 | `ΔACC > −0.005`（容忍 0.5 个百分点）而 NMI/PURITY/簇平衡明显改善 | 倾向采用 tempered 版本 |
| **C** 任何 α>0 都明显损伤 ACC | 例如 0.407 → 0.37 | 停止改 BSSAT，正式固定 `α=0`（BSSAT-r1），直接进模块一。含义是：**cluster concentration 本身就是当前 BSSAT 提升 ACC 的机制之一** |

三种情况**无论哪一种**，下一步都进入 **模块一 Reliability-Adaptive Dual-Graph**。

> 📌 **实际判定结果（100 runs 已跑完）见 §35**：A 未达成（Trento 0.6237 < 0.629）、B 的结构条件未达显著、
> 且"b 的集中度驱动簇集中度"这一前提被机理检验直接证伪 ⇒ **固定 `α=0`（BSSAT-r1），直接进模块一**。

## 31. 与基线 FedRSMVC 的对比

### 31.1 框架级差异

| 维度 | 基线 FedRSMVC | FSRIMVC V5 |
|---|---|---|
| 缺失粒度 | 无缺失（完整多视图） | **像素级缺失，SLIC 之前注入**（影像级缺失） |
| 缺失模式 | — | `random` / `block` / `strip` 三种，缺失像素数精确 = `round(ρ·H·W)` |
| 节点可用性 | 无 | `m_i^(v) = 1[r_i^(v) ≥ τ]`，`τ = 0.5` |
| 建图 | 有向 kNN，特征含 2 维空间质心，输出未归一化 | 无向对称化 kNN，特征不含空间质心，走 `normalize_sparse_adjacency` |
| 局部图 | 全节点参与 | **仅观测节点**构造特征 kNN 图（避免 0 填充假边） |
| 图融合 | 固定公式 | `A = 0.5·A_s + 0.5·A_f^(v)`（下一步升级为逐边 `β_ij^(v)`） |
| 跨客户端对齐 | CSATA（空间单签名 + 行随机 Sinkhorn） | **BSSAT**（空间+语义双签名 + 质量守恒传输 + `α` 调制） |
| 重构损失 | 全节点 | **仅观测节点**（`mask_aware_loss`） |
| 原型拟合 / 评估 | 全节点 | 仅观测节点（`mask_aware_eval`） |
| 背景标签 | 未定义 | 保留（`drop_nonpositive_labels=false`，与基线同口径） |

> ⚠️ **跨仓库绝对数字不可直接比较**：`ρ=0` 时两仓库唯一的差异就在 `adj` 上，
> 根因已定位到 `utils/superpixel_utils.py::create_spixel_graph` 的三处实现差异（§22.3），
> 开关 `FRSIMVC_GRAPH_SEMANTICS=original` 只解释了 29% / 45% 的差距，**余下 0.084 / 0.076 仍未定位**。
> 因此 **A0 不是原版的忠实复现**（用户已明确指令 A0 不改）。
> 任何对比都必须在**同一协议、同一批次、逐 seed 配对**下进行。
> 更细的框架与创新点对照见桌面 `FRSIMVC_vs_FedRSMVC_框架差异与创新分析.md`。

### 35.7 T9 机理检验：`b` **不是**簇集中度的来源（核心负面结论）

大纲v5 的因果链假设是 *"`b` 被主簇主导 → 传输后簇被压向同一 anchor → 簇集中度上升"*。直接检验：

| 检验量 | Trento | MUUFL | 假设预期 |
|---|---|---|---|
| `r(b_p_max, cluster_p_max)` | **+0.171 (p=0.236)** | **+0.003 (p=0.983)** | 强正相关 |
| `r(b_K_eff, cluster_K_eff)` | +0.113 (p=0.433) | −0.138 (p=0.339) | 强正相关 |
| `r(C_T, best ACC)` | +0.028 (p=0.845) | −0.096 (p=0.509) | （v4 曾报显著负） |
| `r(H_T, best ACC)` | −0.144 (p=0.320) | +0.132 (p=0.359) | （v4 曾报显著正） |

- **`b` 的集中度与预测簇的集中度之间几乎零相关**（+0.171 / +0.003，均不显著）。
- 数量级本身就完全不匹配：**`b` 几乎是均匀的（K_eff(b)=5.90/6、10.89/11），而预测簇极度集中（K_eff(cluster)=4.56、4.17）**。集中度必然产生于别处 —— 指向 **双签名对齐 + Sinkhorn 传输本身**（行归一化之后的条件矩阵把多数节点推向少数 anchor），而不是列边际 `b`。
- 顺带：**`C_T`/`H_T` 与 ACC 的相关在本批次上不显著且符号在数据集间不一致**（Trento `r(C_T,ACC)`=+0.028 / MUUFL=−0.096），与大纲v4 报告里"C_T 负相关、H_T 正相关"的结论**不一致** ⇒ 再次确认二者只能作描述量，且该结论本身不稳定。

### 35.8 T8 跨批次复现性：α 的效应量已淹没在批次噪声里

同名义配置（BSSAT-r1，β=0.5，ε=0.1，α 未启用）在两个独立批次上的对照：

| 数据集 | 旧批次(20260918) | 新批次 α=0 | Δmean | p | 逐 seed \|Δ\| 最大 | 节点集均值 |
|---|---|---|---|---|---|---|
| Trento | 0.6289 ± 0.0453 | 0.6221 ± 0.0475 | −0.0068 | 0.2324 ns | **0.0451** | 1167.8 → 1167.8（**完全相同**） |
| MUUFL | 0.4069 ± 0.0240 | 0.4103 ± 0.0216 | +0.0034 | 0.0625 ns | 0.0197 | 1832.0 → 1832.0（**完全相同**） |

- 均值层面差异不显著（Trento p=0.23、MUUFL p=0.063），**但逐 seed 峰值差最大到 0.0451（Trento seed 4：0.6148 → 0.5697）**。
- 节点集完全相同 ⇒ **上述差异与 v3 协议的"节点集随缺失种子变化"无关**，是训练/实现层面的运行间方差。
- 一个值得追的线索：**MUUFL 有 5/10 个 seed 的 best ACC 在两批次间四位小数完全相同**（seed 1/3/4/7/8），另外 5 个不同；Trento 则 10/10 全不同。这更像**非确定性 GPU 归约（Sinkhorn/scatter 的 atomicAdd）在不同随机执行序下偶发分叉**，而非协议或数据不一致 —— 需要后续用 `torch.use_deterministic_algorithms(True)` 或固定 CUDA 随机序来证实。
- **方法论后果（写进口径规范）**：本轮的 α 真实效应量是 **0.001~0.005**，跨批次噪声的逐 seed 量级是 **0.02~0.045**。**在这个信噪比下，任何"哪个 α 更好"的判断都不可靠**，包括本节的结论本身；本节能站得住的只有那些 p<0.01 的项（Trento `acc_final`、`acc_p25`）。

### 35.10 T6 决策判定（大纲v5 §6）

| 判据 | 阈值 | 实测 | 结论 |
|---|---|---|---|
| **A** 双赢 | `ACC_Trento ≥ 0.629` 且 `ACC_MUUFL ≥ 0.407`，且 NMI/PURITY↑、p_max↓、H_clu↑ | Trento 最高 **0.6237**（α=0.05）→ **FAIL**；MUUFL 0.4103（α=0）→ OK | **不成立** |
| **B** ACC 基本不变 + 结构明显改善 | `ΔACC > −0.005` 且 NMI/PURITY/簇平衡明显改善 | 最大跌幅 Trento −0.0048 / MUUFL −0.0043 → **落在容忍区间内**；但 NMI/PURITY 配对检验**全不显著**（MUUFL α=0.2 的 `K_eff`/`H_clu` p=0.0645，差一点） | **字面近似满足、实质不满足** |
| **C** 任何 α>0 明显损伤 ACC | 例如 0.407 → 0.37 | 未出现（跌幅 ≤0.0043） | **字面未触发** |

**判定：三条规则都没有被干净地触发，但结合 35.6/35.7 的机理证据，唯一合理的决策是"不采用 tempered 版本"。**
理由（按重要性排序）：

1. **没有正向收益**：`best-round` ACC 在 8 个（α>0 × 数据集）单元上**无一显著**，MUUFL 的最优点就是对照 α=0 本身。
2. **机理被证伪**：调质想压的簇集中度**不是 `b` 引起的**（`r`≈0），而且 `b` 本身已接近均匀，调制近乎恒等变换（L∞≤0.017）。即使 α 继续加大，也不可能改变簇形态。
3. **唯一的正向证据不可归因于"调质有效"**：Trento `acc_final +0.0467**` 更像是**传输目标平滑带来的训练后段稳定性**，属于过程性改善；而它同时伴随 `best-round` 不变、PURITY 略降。
4. **信噪比不足**：效应量 0.001~0.005 远小于跨批次噪声（峰值差 0.045），任何"选哪个 α"的结论在此样本量下都不可靠（35.8）。

⇒ **正式固定 `α = 0`（= BSSAT-r1），`mass_uniform_alpha` 保留在代码里但默认 0.0，不再作为主线；直接进入模块一 Reliability-Adaptive Dual-Graph。**

> 若后续需要保留一个"温和调质"的备选配置：**Trento α=0.05 / MUUFL α=0.2** 是各自表现最好的点（分别对应 `acc_final` 和 `ARI` 的显著改善）。但两数据集的最优 α 不一致，说明它不是一个有普适性的机制，不应写进主线方法。

### 35.11 本轮的方法论收获（写进规范，避免重复踩坑）

1. **"诊断量 → 机理假设 → 可调参数"这条链必须做直接检验**。本轮若只看 T1 表就会得出"α 影响不大，可能是效应太弱"的模糊结论；正是 T5（调制幅度）与 T9（相关性）两项诊断把"效应太弱"变成了**"作用通道不存在"**的可证伪结论。**以后任何新模块上线前，先写一条"若该模块有效，某两个量应显著相关"的检验并先跑它。**
2. **调制类改动要先报告"改动了多少"**（L∞ / 相对变化），否则容易把"参数没生效"误解为"机制无效"。
3. **best-round 与 final/tail 的分歧是本项目的常态**（§6 已有三次先例）。**主表至少并列 `median` 与末 30 轮均值；报 `best` 必须同时给逐轮 std。** 本轮 Trento `best` +0.0016 ns 而 `final` +0.0467** 就是最新一例。
4. **跨批次方差必须量化**（35.8）。**同名义配置在两次批次上的逐 seed 峰值差可达 0.045 ⇒ 结论显著性必须走配对 + 非参检验，不能只看均值。**

### 36.2 RADG-v1 的数学定义（大纲v6 §1–§5）

节点可靠度直接**复用**缺失模拟器已经算好的**节点观测比** `r_i^(v)`（= 该超像素内被观测像素占比），**不新引入任何网络**：

```
节点可靠度      r_i^(v) ∈ [0,1]            （= node_observed_ratios[view]）
边可靠度        c_ij    = sqrt(r_i * r_j)   （几何平均，大纲 §2 默认）
自适应权重      β_ij    = β_min + (β_max - β_min) * (1 - c_ij)
融合            A_ij^(v) = β_ij * A_s,ij + (1 - β_ij) * A_f,ij^(v)
```

语义：**两端都可靠的边（`c_ij→1`）→ `β_ij→β_min`（更信局部特征图）；任一端不可靠（`c_ij→0`）→ `β_ij→β_max`（更信共识空间图）**。

**实现要点（大纲 §5 的稀疏要求，已严格照做）**：

1. 权重**只在各自图自身的非零边上**计算，再 `A = w_s + w_f` 相加 —— 不做稠密化：两图只要有一条边缺，该 edge 就只拿单侧贡献，与固定融合的稀疏结构天然对齐。
2. 加权完成后，**下游后处理链完全不变**（对称化 → 自环 → 对称归一化）。**没有改动任何图归一化**，因此 RADG 的差异不可能来自归一化口径。
3. 提供 `edge_reliability ∈ {geometric_mean, arithmetic_mean}`（后者 `c_ij=(r_i+r_j)/2`），默认取几何平均；另有 `use_complement` 开关以支持"反向可靠度"的消融，默认关。
4. 参数校验：`β ∈ [0,1]`、`β_min ≤ β_max`、`r` 长度必须与节点数一致、模式名必须在白名单内 —— 任一不满足直接抛错，不做静默降级。

### 36.5 本轮新增的诊断量（大纲 §11–§13）

按 §35.11 的方法论第 2 条（"调制类改动必须先报告改动了多少"），每个 run 都会写出**逐视图**诊断，并压平成标量进 `metrics.json` 便于聚合：

**逐边的调制幅度**
- `β_ij` 分布：`mean / std / p10 / p25 / p50 / p75 / p90`
- **实际达到的边界** `beta_min_actual / beta_max_actual`（用于确认自适应权重真的用满了 `[β_min, β_max]` 区间，而不是挤在中点附近）
- 边可靠度 `observed_ratio` 分布（同上分位数）

**图结构**
- `Δ_A`（相对 Frobenius 变化）、`edges`、`connected_components`、`λ_2`（代数连通度）、度统计（`mean/std/min/max`）

**机理检验（对应 §35 的教训）**
- `corr(r_i, β_node)`（逐节点平均入射 β）—— 期望**强负**（不可靠节点的边更偏向共识空间图）
- `corr(r_i, neighbour_reliability)` —— 检验"缺得多 ⇒ 邻居也不可靠"的传播假设
- `corr(r_i, feature_edge_loss)` —— 检验节点可靠度与**特征图边损失**是否同步

落盘位置：`artifacts/radg_diagnostics.json`（逐视图完整结构）与 `metrics.json` / `diagnostics.json`（压平标量）。BSSAT-v2 那次"诊断量只存在于报告里、没进流水线"的问题已修正：**这些量在每次 run 里自动产生，聚合脚本直接出表。**

### 37.1 大纲v7 的核心改动：Centered RADG（RADG-v1.1）

**公式（大纲 §3–§8）**

```
节点可靠度    r_i^(v)    复用 node_observed_ratios，不引入新网络
边可靠度      c_ij       = sqrt(r_i r_j)
边不确定性    u_ij       = 1 - c_ij
原始权重      β_ij^raw   = β_0 + γ (u_ij - mean(u))          β_0 = 0.5
裁剪          β'_ij      = clip(β_raw, floor, ceiling)        [0.2, 0.8]
再中心化      δ          = β_0 - E[β']  →  β'' = clip(β' + δ)，可重复 2~3 次
最终          A_ij       = β_ij A_s,ij + (1 - β_ij) A_f,ij
验收          |E[β] - β_0| < 0.005（最好 < 0.001），否则 diagnostics 报 warning
```

**关键性质**：`E[β] ≈ 0.5` 被强制保持 ⇒ C-RADG 与 F05 的**唯一实质差别就是"固定 vs 逐边自适应"**，这正是大纲 §14 比较 3 想要的因果对照。

**实现要点（大纲 §8 全部照做）**
- 全程在 **sparse COO 边表**上算，绝不建 `N×N` 稠密 β 矩阵；`E_s ≠ E_f` 时按**无序对 (min,max)** 取**同一个 β**，用排序 + `searchsorted` 映射回各图自身边表；
- 下游**对称化 / 自环 / 对称归一化一字未改**；
- 配置项（大纲 §9）：`radg_mode {centered, uncentered}`、`radg_base_beta`、`radg_gamma`、`radg_beta_floor/ceiling`、`radg_center_tolerance`、`radg_edge_reliability`；旧的 `radg_beta_min/max` **保留**，`uncentered` 模式继续用它（大纲 §0：旧实现不要删，留作失败消融）。

### 37.3 顺手修掉的一个全数据集阻塞 bug：`BestMap` IndexError（MDAS 崩）

扩展数据集时冒烟发现 **MDAS 四臂全崩**：

```
File "cal_metric.py", line 31, in BestMap
    newL2[L2 == Label2[i]] = Label1[c[i]]
IndexError: index 13 is out of bounds for axis 0 with size 13
```

- **与 RADG 无关**：F05（固定融合、RADG 关闭）同样崩。
- 机理：预测的簇数 **多于** GT 类数时（`nClass2 > nClass1`），方阵 Hungarian 会把多余行分配到全零填充列，`c[i] ≥ nClass1` → `Label1[c[i]]` 越界。MDAS 的 GT 有 14 类但其中一类在超像素过滤后没剩节点，实际 13 类，而模型仍输出 14 簇。
- 修法：越界时**退回该簇与 GT 重叠最多的那一类**（`argmax(G[i, :nClass1])`）。
- **零风险**：旧代码在这个分支上只会抛异常，**从来没有产生过数字**，所以 Trento/MUUFL/其他数据集的历史结果**不受任何影响**。

- **同配置重复两次之间最大差 0.0584（第 1 轮就差 0.0583）** ⇒ 即便加 `--deterministic-mode`（内部 `warn_only=True`），本框架仍有显著跨 run 不可复现性（原子加/稀疏 scatter）。
- 因此：§39.4 里两次 30 轮探针 B0 的 0.006 差异属噪声而非泄漏；**跨 run 的绝对数不可比，只有同一条轨迹内的臂间对比可信** —— 这正是 v9 设计八臂共享轨迹的原因。

### 39.7 三条结构性判读（写论文前必须处理）

1. **D0 ≡ E0（恒等，非 bug）**：V=2 视图且缺失节点全部 eligible 时，视图 v 的 donor 就是另一视图的 S̄，覆盖权重下与"对已观测视图做 masked average"逐点相同；全部视图缺失时两者都退化为等权均值。本次所有数据集 `eligible_rate == missing_rate`、`donor_count_mean == row_valid_rate`、`removed_mass_mean = 0` ⇒ **D0 与 E0 在本批数据上逐位相同**。⇒ D0 臂只作"覆盖权重实现正确"的一致性检查，不能作为贡献来源；Module III 的增益只能来自语义投影（C 臂）。
2. **`removed_mass_mean = 0`**：所有全局簇的列边际质量 `b_j > min_valid_mass`，`q_eff = q_raw`，"无效列剔除"机制在这批数据上是惰性的。`min_valid_mass=0.5` 从未生效 ⇒ 若要让该机制真正进入实验，需要把它调到能触发的阈值，或承认它只是安全网。
3. **λ 混杂尺度效应**：逐轮诊断显示 `cosine(h_graph, h_sem) ≈ 0.99`，但 `‖h_sem‖ ≈ 2.6 × ‖h_graph‖`（如 round 30：4.15 vs 10.78）。而 `S_comp = softmax(−d(h_comp,P)/τ)`，范数放大等价于降温/锐化 ⇒ **C 臂相对 B0 的差异里混有"置信度锐化"成分，不全是语义信息**。建议（可选，成本低）：补一个 `h_sem` 按 `‖h_graph‖` 归一化的 `C*_norm` 对照，或在论文里直接把 λ 解释为"语义强度 + 锐度"的联合超参。

### 39.8 耗时与排期

Trento 30 轮：训练 21.7 s（0.72 s/轮）+ 适配器 10.8 s（0.36 s/轮，约 +50% 开销）；伪缺失探针 3 次共 2.25 s。按此外推，300 轮单 run ≈ 5–6 min（Trento），大数据集 2–3×。60 个训练任务 / 6 卡 ≈ **1.5–3 h**。
